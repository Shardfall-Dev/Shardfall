# Shardfall layered armor v1.0 — Claude implementation handoff
Status: original articulated procedural armor graphics, not production hand-painted sprites. This is a standalone versioned asset pack, not a live game patch. Based on classic-humans-v2 (112x100 cell, anchor 56,86, 8 directions S SW W NW N NE E SE, 29 animations). Both bodies use the same pose as the base rig, with body-specific width. Armor is drawn on each moving body segment in depth order rather than pasted over a completed sprite. The export currently produces composite atlases, not individual RGBA painted overlays.

1. Read src/equipment.js, src/rules.js, the current human renderer, NPC renderer, equipment/paperdoll, save/corpse and build pipeline before editing. The existing EQ.SLOTS, EQ.SLOT_LAYER, EQ.RENDER_LAYERS, EQ.appearance, EQ.signature, SF.matOf and EQ.matColor are authoritative. Never introduce duplicate gameplay armor slots or alter protection, requirements, durability, crafting, loot, weight, meditation, movement or mithril balance. Keep previous asset packs and renderer behind a flag.
2. Use armor-layers.mjs and classic-human-rig-armor-v1.mjs as an initial renderer prototype. Supply actor.equip to frameSVG({equip, SF, body, direction, action, frame, weapon,...appearance}). resolveGear reads exact item IDs, material and secondary sec. The standalone palette is a snapshot for preview; live colors must come from EQ.matColor. The actual existing metal colors and names are preserved, including blue valorite and pale mithril. Independent material per piece; studs use secondary metal, not leather tint. Retain outlines, dark joints, directional highlights and non-dyeable trims. No full-sprite CSS hue filter. Clothes dye is a separate future channel; do not silently invent persisted dye fields.
3. Use character equipment as source of truth; visually mix pieces and update immediately on successful equip/unequip, never before validation. Paperdoll and world use the same resolved equipment and material. Keep item instances/UIDs and exact legacy migrations. NPC guards, bandits, merchants and human enemies use the shared renderer and actual equipment or clearly cosmetic presets only where there is no inventory. No monster changes. Do not copy generic guard armor onto characters already using real equipment.
4. Compose per limb with pose-aware front/back ordering. Base body/underwear remains under armor; shirt/trousers, legs/feet, chest/neck, arms/hands, outer robe/tabard/belt, head/hair, cloak and weapon/shield follow direction and pose. Helmet rules suppress hair where covered; refine open helmet face/skin and hair in painted pass. Robe and cloak occlusion need visual QA, especially side/back/death. Two-handed weapons suppress offhand using actual SF.WEAPONS flags in all animation states, not just attack states. Shield is a visual, not a parry rule. Corpses retain last worn appearance until actual loot semantics say otherwise. Do not re-pose corpse from live actor.
5. The procedural rig draws at native resolution. Cache bounded composite atlases by body, appearance, action, weapon, resolved item IDs/materials/secondary colors and direction when applicable; never generate SVG, PNG or image decode in render loop. Atlas rows are 8 male then 8 female directions, columns are animation frames. Use fixed anchor and nearest-neighbor; retain world collision independent of visuals. Validate clipping (long weapons and death) and use larger common cells only via versioned contract migration. Lazy-load, evict unused composites, measure many NPCs. Keep build compatible with the existing fragment-based browser architecture; use module import or bundling consistent with existing build. No new dependencies required.
6. Final art pass: replace procedural shapes with original hand-painted classic isometric pixels matched to the approved human base. Export transparent per-slot per-frame geometry with material ramp masks (primary, secondary, non-tint), split near/far limbs and hand/weapon depth. All layers share anchor, direction, frame timing and canvas. Do not rely on an image-generation sheet of independently posed figures as a runtime overlay. Do not claim final painted art already exists. The current pack is usable for prototype integration and atlas export, not pixel-perfect painted UO art.
7. Test both bodies, all 8 directions, all 29 animations, every current equipment definition and the 10 metals, all hides and woods, mixed plate/leather, independent studs, helmets, shield/two-hand restrictions, robe/cloak, casting, walking, attack, death/corpse, paperdoll, NPCs, load/save, item identity, inventory and combat regression. Report unsupported definitions, visual bugs and screenshots; include existing test results and measured performance. Keep old renderer until accepted. Commit only tested integration; do not overwrite existing systems.
Preview: serve this folder via local HTTP server; open preview.html. Choose pieces independently or apply a set. PNG/SVG buttons export current animation as composite atlas. Current preview is functional source, not a pre-rendered PNG collection. Jewelry has simplified tiny markers; necklace, ring and bracelet are provisional. No live game QA performed.
