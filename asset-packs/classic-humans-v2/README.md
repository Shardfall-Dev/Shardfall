# Shardfall classic humans v2.0 - implementation handoff

This package supplies original articulated procedural preview sprites for both body types, 8 screen directions, and 29 animation states with 29 weapon shapes. All appearance options are generated as layers, not a baked combinatorial explosion. This is a functional starter rig, NOT the final hand-painted UO art set. Preserve the v1 painted asset pack and the new painted walking/casting sheets separately; use this rig to establish animation and equipment contracts, and replace its visual layers with consistent painted atlases after approval. No existing game files are modified by this package.

## Claude instructions
1. Inspect latest main, locate item definitions, player/NPC rendering, human-vs-monster classification, saved character appearance, and character creation. Keep all existing simulation, AI, combat, skill/stat, inventory, equipment, targeting, collision, quests and save data. Do not fork separate NPC/player renderers.
2. Import classic-human-rig-v2.mjs into the appropriate asset/renderer module. Use frameSVG for previews, atlasSVG + svgToPNG to export/calculate sprites. Cache atlas images by stable appearance + weapon + action keys; do not generate SVG or PNG in the render loop. Keep a bounded cache and async loading, nearest-neighbor at target native resolution. Use the fixed ground anchor, translate world-facing into screen direction. Test every direction at actual game scale against monsters and world tiles.
3. Map EVERY existing weapon ID from the authoritative item registry: swords, axes, fencing, mace weapons, staffs, archery, heavy crossbow, shields, unarmed and tools. Use the existing weapon metadata, not item name guessing in combat. Use attackForWeapon for animation category and distinct weapon geometries; unsupported weapons must be reported, not silently mapped in final release. Two-handed equipment uses two-handed stance and hides incompatible shield; shield block is visual only.
4. Animation priority death > hit/interrupt (only if simulation says interrupted) > attack/cast/tool > ready > run/walk > idle. Animation playback is visual only. Keep combat cooldowns, spell cast times, hit events, projectile releases and resource costs authoritative. Use simulation timestamps to sync visual phases and cast interruptions. Spells share body gestures (one hand, two hand, staff) and separate spell-specific effect assets; do not create a new gameplay rule for each animation. Ranged projectile origin is the weapon/hand socket. Death corpse keeps last appearance; corpse visuals must not affect loot.
5. Character creation: male/female body, hair style/color, skin tone, beard when desired, independent cloth palette. Keep skill/stat allocation from new UO-style creation system; appearance is cosmetic. Add preview rotation, animation preview, randomize; persist stable appearance IDs and migrate old saves without loss. Do not reroll appearance when loading. NPC role presets are starting defaults only, use persistent IDs/seed for colors, hairstyles and skin; all human enemies use same renderer. Nonhumans retain existing assets.
6. Make profession-appropriate equipment (guard, smith, miner, carpenter/lumberjack, merchant, mage, healer, sailor, farmer, villager, bandit, ranger, innkeeper, priest, scribe). Use existing NPC definitions and gender rather than changing identity. Prepare equipment/hair layers for later art upgrade; don't claim missing layered plate/chain/etc art is included. Respect player privacy/settings.
7. Test sprite sheet frame boundaries and anchor, all 8 directions + body types, every weapon item, walking/running while changing direction, hand grips, handedness, cast interruption, hit/death/corpse, appearance save/load, old saves, NPC interactions, paperdoll, mobile and desktop. Check no monster changes. Do not delete the old assets until all references are migrated and visual quality approved. Keep fallback renderer behind feature flag until acceptance. Commit tested integration and report missing art, mapped item IDs, changed files, performance and screenshots. Do not claim a finished painted sprite atlas from this procedural preview.

## How to view
Serve this folder with a local HTTP server (ES modules). Open preview.html. Choose body, direction, action, weapon, hair, cloth, skin, beard and outfit. The preview can export current animation as an eight-direction SVG atlas or PNG atlas. It is not game integration.

## Repository audit addendum
Current src/rules.js SF.WEAPONS contains 16 IDs; WEAPON_MAP covers all: sword, glaive, battleaxe, hatchet, knife, pickaxe, hammer, mace, waraxe, dagger, kryss, spear, shortbow, crossbow, heavycrossbow, unarmed. Preserve exact IDs and their two/ammo/skill flags. Hatchet is two-handed in the existing rules. For pickaxe use chop1h in combat and mine when gathering. Equipment render layers already exist in src/equipment.js EQ.RENDER_LAYERS and EQ.SLOT_LAYER; reuse them rather than creating duplicate slots. The game is assembled from script fragments; integrate a module only after inspecting build order and tests. The ZIP is source + preview + metadata; it exports PNG atlases in a browser and is not pre-rendered painted combat art. The separate painted pack contains 8-direction idle, 2-direction walk/cast and heuristic clothing recolors; it is not included in this repository ZIP. Do not mix styles in a final release. Generated SVG frame strings passed sanity checks; browser/game visual QA remains pending.
