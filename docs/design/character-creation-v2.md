## 2. Shared progression contract
Use the canonical progression configuration and registry from skill/stat reworks. T2A creation default: exactly 65 base stat points, integer STR/DEX/INT each 10–45; runtime total 225 and individual 100 (confirm with latest stat design). Exactly 100.0 real skill points among 2 or 3 distinct implemented/selectable skills, 0–50 each, integer starting allocation; 50/50/0, 50/49/1 and 40/30/30 legal. All others start 0.0. Runtime 100.0 per skill, 700.0 total, +0.1 increments. Use integer tenths internally (newChar currently multiplies by 10); no double conversion. Initialize locks Raise using canonical enums. Stat locks per stat system. No purchased stat gains; skill trainer policy belongs to skill rework, not this UI. Do not retain free stat lessons or old 150 starting pool. Do not apply creation limits to migrated existing characters. Use real skill values for allocation and show derived values separately. Preview HP/stamina/mana/carry using shared SF.maxHp/maxStam/maxMana/EQ helpers after stat rework; no formula in UI. If T2A raw attributes are adopted, starting HP may be much lower: test early content, not inflate stats.
Historical reference: original Second Age manual https://www.mocagh.org/origin/uosecondageuk-manual.pdf (65, min10 max45); contemporary FAQ https://www.neoseeker.com/uo2a/faqs/40325-ultima-online-beginner.html (100 across three); https://wiki.uosecondage.com/Category:Stats (225/100); UO 80 start was later https://www.uoguide.com/Client_Patch_3.0.4m. This is a chosen early T2A configuration, not later UO.

## 3. UX wizard
Main entry: Continue existing hero (if valid), New Character, settings/back as appropriate. Do not overwrite existing save on opening creator. Four stages: Identity/Appearance; Starting Profession; Stats & Skills; Starting Town/Review. Back/Next always preserve draft; keyboard and touch, no full page redraw during typing or dragging; responsive desktop landscape and mobile, no horizontal overflow. Original dark wood/stone framing, parchment content, aged brass, restrained gothic headings, readable values; own Shardfall art not copied UO assets. Persistent step indicator; clear large buttons; errors inline and focusable. Desktop two columns paper doll and controls; mobile stacked with bounded content, sticky navigation, no endless scroll. Preview front/isometric and rotate if directional art exists; show same look in paper doll and world when supported.

Identity: 2–16 visible characters, trim, allow letters/numbers/spaces/apostrophes/hyphens according to current policy, reject invalid/empty/control chars; escape HTML. Human only for now. Male/Female selection, skin tone, hairstyle, hair color, male facial hair/style/color (none supported; female hides/clears beard by design), shirt/trousers or skirt if item exists, cloak optional. Palette swatches with selected state and accessible labels. Original male/female sprite families, same scale, anchor, direction/frame order, animation timing, footprint and collision. Persist look {body, skinTone, hairStyle, hairColor, facialHairStyle, facialHairColor, clothingColor, cloak}; stable IDs with allowlists; preserve unknown legacy appearance fields if safe. If art missing, do not claim it exists: use explicit temporary compatible fallback, no broken images; document missing sheets/layers. Prefer existing renderer; no new renderer pipeline. Cosmetics never affect stats, gear, targeting, movement, damage, weight or skill caps. Preview/appearance selection must not instantiate gameplay items.

## 5. Allocation
Stat sliders and +/-1, optional numeric keyboard entry, with remaining points counter; allow reducing one to free points, then increase another; clamp no over-budget; reset selected preset; final exact 65. Skill list search/categories with canonical UO names, real descriptions/usage and lock status explanation; three unique selections, empty row allowed only when zero, +/-1 sliders 0–50, exact 100. Filter duplicate options or reject atomically; no phantom/unimplemented skills selectable. Skills renamed in parity branch must use its aliases/migration centrally, e.g. Spellcraft→Magery, Spell Focus→Evaluating Intelligence, Wardcraft→Resisting Spells, Smithing→Blacksmithy, Woodcutting→Lumberjacking, Concealment→Hiding. Never duplicate skill entries or fork registry. Shared pure validateCreation(payload) rejects NaN, infinity, malformed values, unknown IDs, duplicates (before object aggregation), invalid appearance/town, invalid budgets and fractional starting points. Same function used for UI and boot; future server validates untrusted input. Keep final button disabled with visible reasons until all valid.

## 6. Starting towns and equipment
Use existing ANN/world registry and navigable town/spawn/shrine identifiers; show actual map, safe starting places and short descriptions. Saltmarsh Quay current verified default, with existing starter quest and Wren hook. Other towns only unlock when implemented, walkable and have tutorial/services (bank, vendor, healer, travel route), show unavailable instead of inventing coordinates. Recommended town by template is optional, never a lock. Set position, sector, bound shrine and quest flags consistently before population/boot; do not fire Quay quest outside its zone. If only Quay ready, skip redundant selection or show it as only available.
Shared skill-driven starter kit manifest: common plain clothes, journal, food, modest gold (propose 100), bandages (propose 10), basic weapon/tool based on positive skills; swords/daggers/maces/bow+arrows, mining pickaxe, smith tongs, hatchet, sewkit, etc; Magery spellbook and limited reagents/implemented low-circle spells, no high spells; lockpicks/instrument only if items implemented. Resolve real item IDs. Deduplicate tools, avoid grants for zero skills, no expensive materials, no automatic unusable weapon, shield only with legal one-handed setup. Check stat requirement and total carried weight at min STR; choose light starter weapon or pack it if legal, trim optional supplies; never start overloaded. Starter economy policy: grant once on committed character creation; basic starter items no vendor resale if supported via per-instance flag, ordinary full-loot behavior unless existing policy says otherwise. Do not alter global item definitions. Hotbar references only actually available items/spells/actions. Test each preset including non-combat start.

## 7. Persistence and architecture
Keep draft transient, separate from gameplay state; do not generate or tick world behind wizard. Only final validated create calls boot/newChar and starterKit exactly once. Disable repeated submit; preserve old save until new boot/save succeeds; confirm destructive replacement explicitly, export old save if supported. Single local character slot remains current scope; future character IDs/slots/account authority designed for later multiplayer, no network implementation now. Use versioned save migration for missing appearance fields and registry aliases, idempotent and preserve existing name/stats/skills/locks/inventory/equip/position/quest/ghost/world. Do not silently clamp legitimate existing stats to creation range. If latest progression cap migration needed, delegate to stat rework. Continue must never regrant starter items or reset stats. Keep CSS and creator logic modular in repository conventions; update index/build scripts for browser bundle if split. No dependency added merely for UI.
