## Implement
Replace manga/anime human player and human NPC rendering with the classic painted UO-inspired visual direction; keep every nonhuman monster unchanged. Use one human renderer for player, friendly NPCs and hostile humans. Preserve gameplay, AI, collision, targeting, quests, stats, skills, Magery, equipment, save format and existing combat timings. Use a feature flag for the new renderer pending visual acceptance.

Establish an eight-direction shared animation contract and fixed ground anchor. The v1 atlas has 48x80 cells, anchor (24,76), two body rows and eight direction columns. The painted v2 walk/cast atlas has 80x80 cells, anchor (40,76), eight time columns, and the explicit body/action/direction rows in its manifest. Its SE sequences are painted and SW is mirrored (handedness changes). The other six walk/cast directions, all painted weapon attacks, and isolated hair/equipment layers are missing. Do NOT label these files a complete painted animation set or invent missing assets. The rig covers 29 animation states and 35 IDs, including the 16 weapon IDs present in the prior src/rules.js audit; re-audit current SF.WEAPONS and map additions. Use rig for testing contracts only, and do not mix procedural and painted styles as final art. Retain prior renderer for unsupported states until matching art is available; report exact missing states, and use only visually approved fallback behavior.

## Layering — mandatory before armor production
The painted bodies have clothing and hair baked in, so do not treat them as naked/bald compositing bases. A new matching base-body set and isolated apparel/hair/equipment overlays must be produced for final modular art. Reuse existing EQ.RENDER_LAYERS and EQ.SLOT_LAYER (verify current definitions); define a versioned atlas contract with bodyType, action, direction, frameIndex, canvas dimensions, anchor, per-direction draw order, occlusion masks and hand sockets. Each piece must align to the exact same body pose/frame and coordinate origin. Hair/beard, skin, undershirt/trousers, head, neck, torso, arms, gloves, legs, boots, outer robe/tabard, cloak, weapon and shield are independent layers. Direction-dependent near/far hand and cloak depth matter. Support any combination (plate chest + leather gloves + chain legs, etc.) and material palettes using tint masks, not entire-body recolors. Use existing item material/slot data and keep item stats unchanged. Support helmet hair hiding, robe/cloak occlusion, two-handed grips and shield compatibility. The paperdoll must derive appearance from the same equipment state, using matching portrait-specific art rather than stretching world sprites.

Character creation and NPCs: persistent male/female body, hairstyle, hair color, skin, beard, independent clothing colors, seeded role-based NPC appearances. Preserve named NPC identities and faction colors. Make guard, merchant, mage, healer, miner, blacksmith, farmer, sailor, bandit variants. Do not change skills/stat allocation. Render world at native resolution with nearest-neighbor and cache composited textures; do not generate every frame.

Test all current weapon IDs, body types, directions, actual scale/anchor, animations, casting interruption, equipment slot changes, mixed armor, paperdoll, save/load, old saves, mobile/desktop and monster regressions. Commit implementation separately and report exact changes and missing art. No game code has been modified by the asset-only handoff.
