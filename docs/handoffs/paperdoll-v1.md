# Shardfall classic paperdoll v1.0 — art and integration contract

Status: design specification and original painted reference portraits; independent production overlays are NOT complete. The portraits are supplied separately as Shardfall_Paperdoll_Art_v1.zip (four transparent 384×512 PNGs). They are flattened references, not compositable layers or evidence of any equipped item. Do not copy Ultima Online's actual assets. Use its classic grounded aesthetic as inspiration.

## Inspect and reconcile
On main at review, src/equipment-ui.js renderEqWin renders SCOUT_SRC in .eqfig; equipment slot controls already exist. src/equipment.js exposes EQ.SLOTS, EQ.appearance, EQ.signature, EQ.matColor, EQ.twoHanded and validated commands. Read current branch, src/rules.js, creator, world renderer, build.sh and asset-packs/classic-humans-v2/manifest.json and asset-packs/layered-armor-v1/manifest.json. The requested assets/character/missing-character-art.json was not present on main at review; locate it in current working tree before changing it, respect its actual sizes/formats and enumerate unresolved entries. Do not overwrite or mark entries done unless verified. The older rig packs are procedural prototypes, not finished painted art.

## Art contract
Separate high-resolution paperdoll pose from 112×100 animated world rig. Proposed paperdoll canvas 384×512 RGBA, feet baseline 496, fixed three-quarter standing pose, common anchors per body. If current manifest specifies another size, follow that instead or migrate versioned. Male and female body with modest neutral underwear (no baked-in hair, armor or weapons). Natural anatomy, muted medieval colors, painterly pixel texture, crisp silhouette, top-left lighting. Separate skin, eyes/face where supported, hair (all actual creator options), beard, starter clothing, boots and cloak; no default hood concealing choices. Hair front/back masks and helmet occlusion; visible beard only if helmet permits. No anime, giant weapons, plastic gradients or baked background. Weapon grips and shield straps must line up with hands. One-handed and two-handed resting poses can have distinct registered hands; retain identical body proportions and anchors. Separate painted gear layers for each actual item and both bodies, no flattened full suits. Preserve geometry and motifs of matching in-world designs, including each helmet, shield, weapon and armor silhouette.

## Single source of appearance
Read actor appearance and actual actor.equip (18 existing slots). Keep validated EQ commands, stats, saves, crafting and item identity unchanged. Build one pure resolved appearance descriptor used by creator, paperdoll, world and human NPC renderers: body/skin/hair/style/beard/clothing colors plus each item id, slot, material, secondary material, dye only if supported, exact visual key and visibility. Resolve materials via SF.matOf and EQ.matColor, fixedMat, it.sec; weapons via SF.weaponOf and real weapon map. EQ.appearance currently omits secondary material and some visuals (e.g. jewelry); EQ.signature is UID-only except broken flag, so create a separate appearance cache key or extend visual signature to include actual visual fields and asset revision. Do not use item UID as the sole visual key. Do not create a second equipment inventory or infer items from portrait pictures.

## Equipment coverage
Generate registered layers for every live wearable definition and weapon, not just families. At minimum cloth, leather, studded, bone, ringmail, chain, plate, dragon scale, all helmets, shields, boots, jewelry, robe/tabard/cloak/belt. Include sword, broadsword, katana, rapier, greatsword, dagger, kryss, axes, maces, hammers, spears, polearms, staffs, bows, crossbows and applicable held tools from the actual weaponMap. Match real game IDs; don't add gear merely for visuals. Treat wooden bow limbs, wood shield body and staff separately from metal heads, leather grips and strings. Independently tint the primary channel (metals iron through mithril, hides, woods) and secondary studs. Use aligned grayscale shading and mask textures per material channel; preserve alpha, outline, specular and fixed trim, never full-sprite CSS hue filter. Draw back hair and cloak, body, underclothing, leg armor, footwear, torso, neck/arms/hands, outer robe or tabard, belt/jewelry, front hair/headgear, weapon and shield in pose-specific order. Split cloak and hands/grips into sublayers as needed. Hide offhand on actual two-handed weapon and do not invent quiver inventory. Handle ghost and corpse without showing live equipment incorrectly.

## UI integration
Replace the SCOUT_SRC doll in renderEqWin with a registered layered compositor (Canvas or stacked images with bounded cache). Keep EQ_LEFT/EQ_RIGHT/EQ_BOTTOM and all existing drag/drop, double-click, right-click, tooltips, durability indicators, and stats. Classic dark leather/wood frame, restrained bronze edges, full-body central figure, distinct square gear slots, large close button, name/title, armor/weight and compact stats; mobile responsive, draggable desktop, no forced scrolling for description. Creator uses same base renderer with current selected appearance and preview equipment, but does not mutate saved equipment until creation confirms. Actual world character must reflect successful equip/unequip after integration. If layer unavailable show explicit missing-art indicator and leave item in real slot; never show a visually different item as if it were the same. Keep documented old world fallback until actual assets exist. Never present reference outfits as real dynamic art.

## Acceptance
Validate manifest entries against actual PNG files, RGBA dimensions and matching anchors, mask sizes and all known item IDs; build and run existing tests. Screenshot both bodies, all creator hair/skin options, naked/underwear, mixed armor, iron/valorite/mithril same piece, independently colored leather and studs, multiple woods, sword/shield, bow and two-hand change, equip/remove, save/load, ghost and corpse, NPC, phone and desktop. No changed item counts, combat or inventory rules. Report exact missing overlays and test results. Keep procedural and flattened reference art explicitly separate from finished production assets. Version assets and preserve prior packs.
