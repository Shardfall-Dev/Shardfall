## Prioritized defects / risks
1. P1 intermittent UI test: tests/ui-smoke/run.py:246-253 arms against a boar, records its HP before Playwright clicks close, then asserts HP and target unchanged after 40 simulation steps. The immediate assertion that P.armed=false, P.sel=null and target frame disappears passes. src/hud-ui.js:168-172 and src/game.js:442-447 disarm and prevent new armed swings. But src/npcfight.js:125-143 allows guards to independently damage/retarget the boar; src/game.js:482-510 allows independent creature decisions, recovery, loss of LOS, and target changes. Also real simulation may advance between the HP snapshot and click. These are plausible causes, not a reproduced root cause. Isolate fixture on clear ground away from other actors, freeze/control ticks where possible, record ActorDamaged source IDs after close, test independent enemy AI separately. Repeat 20+ times. Explicitly decide whether already-launched projectiles are allowed to land. Do not remove guard behavior or weaken the assertion without equivalent coverage.
2. P1 deployment: .github/workflows/pages.yml:23-29 calls CI with smoke_advisory:true; ci.yml:45 allows failure. After stabilizing fixtures, require stable functional smoke checks and main protection. Keep performance/timing diagnostics separate. Note Pages succeeded in this particular run, so no known broken production deployment.
3. P1 migration coverage: tests/skills-smoke/run.py:10-15,92 tries main, HEAD~1 and b362b46; fetch/resolve full historical commit, explicitly supply fixture path; fail required CI if missing. Preserve v1–v9 migrations; do not remove legacy fields before migration.
4. P1 save durability: src/game.js:2961-2977 returns false on storage failure, but boot at ~3080 calls save() then returns true. src/creation-ui.js:204-212 treats boot success as creation success; backupRaw return ignored. Risk: a newly created character appears successful without durable save (particularly if quota/storage fails). Verify with forced quota/denial; distinguish unsaved state, preserve original, offer export and retry. Storage handler at game.js:2980 only locks on a non-null foreign-tab save; deletion from another tab is ignored. Add two-tab deletion/replacement test and prevent stale tab recreating deleted characters. These are static findings, not runtime reproduced here.
5. P2 pet persistence defect: game.js:2973 saves relative offsets, not identity/absolute position; boot ~3070 snaps pets 12+ tiles away beside player even when order=stay. petTick:907-921 also teleports followers beyond 24 tiles, direct movement rather than shared navigation. Preserve absolute stay location, stable identity/owner, validated zone travel, loyalty, and migrate old saves.
6. P2 rendering: gear-render.js:16 default false; procedural world sprites and wardrobe only via New art switch. Cache fallback may visibly swap art styles during strip generation. Painted candidates incomplete and developer-only; don't enable by default until visually approved.
7. P2 shops: game.js:2417-2420 uses static SHOPS/SF.PRICES despite NPC resource production; counter access and valid purchase quantity/stock-list wrappers already exist at 2487-2494. Connect finite stock to economy rather than replacing working crafting. Verify sell allowlist, atomic inventory/weight/gold and display quote parity.
8. P2 test/architecture debt: src/game.js 3,113 lines / 378 KB; generated inline assets and 11.17 MB HTML; profile actual low-end mobile startup, frame time, memory, cache churn and three-day world soak before splitting modules. Build artifacts generated through build.sh. Upgrade actions versions and verify. No broad rewrite.

## Gameplay completeness
- Working baseline (tests passed): 49-skill framework, stat locks (225 cap), creation (five towns, templates), weapon combat, equipment/weight/repair/materials, Magery, quests/travel, NPC schedules, wildlife ecosystem, guard-vs-creature combat. Not equivalent to complete UO or live MMO.
- Living World phase 5 partial: src/npcfight.js explicitly prevents player/pet attacks on townsfolk; knockdowns not real NPC deaths. Need criminal/witness/murder/karma/fame, NPC spellcasting, adventurers, NPC deaths/corpses/loot; then phase 6 durable world state/optimization and phase 7 events/economy.
- Taming improved in v0.33: 11 species thresholds, five-pet cap, loyalty/feeding, Animal Lore, Veterinary/control chance. Do not redo these. Missing multi-stage tame, retame history, stable/ownership lifecycle, mounts/pack animals, robust pathing, correct stay persistence.
- Skill gaps documented: karma/fame, map grades practical use, fishing treasure catches, creature spellbook AI, player-to-player skills. Distinguish existing treasure chest/digging mechanics from unfinished map use.
- Magery: other-player resurrection, owned house containers/locks/traps, PvP law, persistent statuses and summons, NPC spellbook AI. Current prepared/held spell cancellation semantics documented; preserve.
- Need living finite economy, expanded dungeon interiors, housing/ownership, player guilds/reputation, player-controlled ships; older sandbox audit is a roadmap, not a current verified complete absence list. Recheck each before implementation.
- Critical MMO gap: current single-player client, one localStorage character, no server authority or multiplayer replication in tree. Before public multiplayer: server-owned movement/combat/skills/transactions/loot, auth, database, durable IDs and concurrency/idempotency, reconnect, abuse prevention and two-client tests. No shared economy on client trust. Keep current offline version as test client.
