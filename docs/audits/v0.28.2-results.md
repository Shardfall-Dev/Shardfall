## Test-suite defects found and fixed
- `tests/combat-smoke/reload.py` read `main:Shardfall_v0.16.html`, which no longer exists on main, so combat-smoke failed before running any check (also on v0.28.1). Pinned to commit 70c5d60.
- `tests/sfx-smoke/run.py` always exited 0, even with failed checks. Now exits 1 on any failure. Its "whiff" check counted the rooted rat's blow on the player as an impact of the player's swing; it now ignores impacts paired with `player.hurt`.
- `tests/combat-smoke/run.py` and `tests/magery-smoke/run.py` cut sub-test output to 1500 / 300 characters, hiding which check failed. They now print it whole.

## Soak (`python3 tests/soak/run.py Shardfall_v0.28.2.html --days 3`), headless desktop, 2 CPUs
72 game hours (432,000 fixed 50 ms steps), player moved between travel places every game hour, save and reload at hour 36. Wall time 850 s. 9/9 checks pass.
- Simulation step: mean 1.82 ms; worst hourly p95 3.6 ms; single worst step 50.6 ms (isolated spike).
- Drawing (`render()`, 60 calls every 4 game hours): worst p95 32.7 ms; page frame loop over 300 frames: mean 16.7 ms, p95 16.7 ms, max 33.3 ms. Headless software rendering — not a phone measurement.
- JS heap after forced GC: 52.1 MB at start, 52.6 MB at the end; no upward trend across 72 hours.
- Actors: ~1,050 throughout (≈945 creatures, 72 townsfolk); corpses cycle 2–46.
- Path search: queue at most 2, cache at its 256 cap. Message log ≤ 46 lines, effects ≤ 5, audio `lastTake` 32 entries.
- Save size 30 KB. No page errors, console errors or frame-loop errors. No failed game asset requests. The only failed request was the Google Fonts stylesheet, which this machine's network blocks (not a game asset).
- Hiding the page saves and releases the stick; losing focus releases it too.
Not measured: real phones, real GPU frame times, iOS audio unlock, AAC decoding on Safari.

## Open issues
1. **Intermittent combat play-test** (`tests/combat-smoke/playtest.py`, real-time phone play-through). In two alternating head-to-head batches on this machine it passed 12/12 on v0.28.1 and 12/12 on v0.28.2, and it passed on GitHub Actions. Outside those batches it failed now and then on builds with the fixes (3 of 14 unmodified runs of v0.28.2; 2 of 7 of the pre-bump fixed build), mostly in full-suite runs or with other jobs competing for the 2 CPUs. Three different failure modes were seen: the halberd killed the rat before the test read the selection (`tapped: null, armedOn: false, slain: true`, a race the test's own comment mentions); the fight ended without the player's kill (`slain: false, armedOn: rat`; attack disarms when the target dies to something else, flees or hides); and a tap on the arrow purchase button timed out. No code changed in this release touches combat, targeting, arming or the shop panel's drawing, and an instrumented copy of the starter fight passed 22/22, but the cause of the uneven failures is not proven. Needs a seeded, deterministic version of this test.
2. **One magery-smoke failure** in the final full run whose detail was truncated by the runner (now fixed); not reproduced in 4 further runs.
3. Two tabs: the older tab stops saving when the newer one writes, but both stay playable; nothing merges their progress.
4. Shop hours are not rechecked while a shop panel stays open; duplicate uids between Wren's gear and the player's are counted for the next uid but not repaired.
5. Not done (out of scope or needs devices): real-device performance baseline, the 67 missing equipment icons, GitHub Pages enablement (owner decision), and the `game.js` modular extraction recommended by the audit.
